## 화면 — 채용 플랫폼형

사람인·잡코리아에 익숙한 구직자가 바로 적응하도록 잡보드 문법을 따랐다.

- **좌측 필터 사이드바**(직종·지역, 각 건수 표시) + **카드 그리드** 2열
- **D-day 배지**가 카드 좌상단. 2일 이내 빨강, 6일 이내 주황, 마감일 미상은 '마감일 확인'
- 카드마다 **'공고 보기' 버튼** — 누르면 원문으로 이동
- 상단 고정 헤더에 로고(SVG 심볼)와 검색, 그 아래 요약 스트립(모집 중 / 3일 내 마감 / 오늘 등록)
- 모바일에서는 사이드바가 숨고 **필터 버튼 → 접이식 패널**, 카드 1열, 검색창은 헤더 아래로
- 필터 상태가 주소창에 남아 공유·북마크된다
- 375px에서 가로 스크롤 0 (실측 확인)

## 동작 원리

```
discover.mjs   각 기관 메인·사이트맵에서 '채용/구인/모집' 게시판을 자동 발견 (인력풀·구직은 제외)
collect.mjs    발견된 게시판 목록 페이지 파싱 → jobs-raw.json
detail.mjs     각 공고 상세에서 '마감일자' 필드 추출 → jobs-detail.json
build.mjs      결과공고 제외 · 직종/학교급/지역 분류 · 만료 판정 → jobs.json
```

**게시판 목록을 하드코딩하지 않는다.** 교육청이 게시판을 새로 만들거나 옮겨도 자동으로 따라간다.

## 데이터 처리에서 중요한 것들

- **결과·안내 공고 제외**: "최종합격자", "필기시험 시간", "채용후보자 등록" 등은 지원할 자리가 아니라 걸러낸다(56건).
- **지역은 제목에서 뽑는다**: 본청 게시판에 올라온 `[구미-도산초]` 공고는 지역이 '구미'다.
  게시판 소속으로만 판정하면 전부 '경북교육청'이 되어 지역 필터가 무의미해진다.
- **직종 중복 정리**: '협력강사'는 `시간강사` 규칙에도 걸린다. 더 구체적인 분류가 있으면 포괄적인 것을 버린다.
- **마감일이 없는 공고**: 게시판이 마감일자 필드를 안 채운 경우다. 숨기지 말고 '마감일 확인'으로 표시하고,
  등록 30일이 지나면 만료 처리한다.
- **본청·지원청 중복**: 같은 공고가 양쪽 게시판에 올라온다(URL이 달라 앞 단계에선 안 걸러진다).
  제목을 정규화(공백·괄호·'재공고'·'N차' 제거)해 마감일과 묶어 제거하고, **지역이 더 구체적인 쪽을 남긴다**.

## 마감일 파싱에서 실제로 틀렸던 것들 (원문 대조로 발견)

1. **계약 종료일을 접수 마감으로 오인** — 의성북부초를 `2027-02-28`로 잡았는데 실제 접수는 `8.3~8.7`,
   2027년은 근무 종료일이었다. → 접수기간 구간에서 '계약/근무 기간'이 나오면 거기서 끊는다.
2. **전각 물결표(～)를 못 읽음** — 원문 상당수가 `7.31 ～ 8.3` 처럼 전각을 쓴다.
   이것만 고쳐도 마감일 확보율이 37% → 62%로 올랐다. `[~～〜∼–—]` 를 모두 인식할 것.
3. **원문 자체의 연도 오타** — `2026.7.20 ~ 2025.7.31` 같은 공고가 실재한다.
   마감일이 등록일보다 빠르면 다음 해로 보정을 시도하고, 그래도 이상하면 버린다.
4. 등록일 + 180일을 넘는 마감일은 신뢰하지 않는다(계약기간을 잘못 잡은 것이다).

## 갱신

```bash
node collect.mjs      # 게시판 자동 발견 + 목록 수집 (약 1분)
node detail.mjs       # 상세에서 마감일 추출 (약 3분)
TODAY=2026-08-01 node build.mjs
node server.mjs       # 로컬 확인 → localhost:4322
```

자동 갱신은 `.github/workflows/update.yml` 에 준비돼 있다(매일 07:10 KST).
**전체 300건 미만이거나 모집 중 50건 미만이면 커밋을 중단**한다 —
게시판 구조가 바뀌면 파서는 에러 없이 0건을 반환하고, 그대로 커밋하면
'오늘 공고 0건'인 멀쩡해 보이는 빈 페이지가 배포되기 때문이다.
